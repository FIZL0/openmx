## What the original does

`research/oracle.txt` `# F31b5q` has it in full. Recipes: `./kit fn 0x514e40 -o atv`,
`./kit fn 0x514ac0 -o atv`, `./kit fn 0x514910 -o atv`. The float order comes from `./kit dis` on a
scratch config (memory note "disassemble untamed": SLUS-21104 with `./kit dis`).

- Exits early when the batch is off, the game is paused, or the batch is forced-only without force,
  or the count is ≤ 0. The fourth argument (kind, 2) is never read.
- Look: compares the batch's scales, half sizes, tint and pair to each table entry, within four
  tolerances read from RAM (10, 0.1, 5, 10). A match stamps the entry's use with the clock. With no
  match, it adds an entry, or with 46 it reuses the stalest (older than 10,000, or the oldest).
- Fill: twelve particles to a slot. It always writes from the slot's first place, even when the slot
  already holds some: a quirk, kept.
- After each fill, the slot's stamp becomes the latest particle life. A full slot (or a fill that
  packed nothing) moves on to the next slot, skipping slots still ahead of the clock unless `+0x78`.

## How it was proved

- **Oracle** `the_batch_send_is_the_originals` (tests/mxvatv_bike_ride.rs): 12,000 generated batches in a
  zero area of state 4's RAM, run through SLUS-21104's send and the port. Every word of the batch, 64
  particles, the 46-entry table, 6 slots and stamps, and the pause word compared. All nine paths reached
  ≥ 461 times (not sent, one slot, moved on with stale kept / skipped, slot full on entry, look found /
  new / table full / table full with a stale look). Passes.
- Mutants: dropping the stale pick and masking the flags half both fail the oracle. Two tie-only or
  equivalent mutants (`<=` vs `<` on the stale age; dropping the "packed nothing" move-on) pass, as
  they must: no float tie is generated, and a fill packs nothing only when the slot is already full.
- **Replay**: `ride/flip_replays_in_pure_rust` run by hand (`--ignored`). Both stay bit-exact on every
  row (flip wrecks on 125, put back on 193), read watch clean. 310 sends in Rust on ride-2, 123 on
  flip-1. Interpreter instructions:

| | before | now |
|---|---|---|
| ride-2 | 546,207 | 145,189 |
| flip-1 | 245,874 | 126,962 |

The two tests stay `#[ignore]`d: the interpreter still runs F31b5r..u's calls.

## Not verified / not 1:1

- Float ties in the look and slot compares (`<` vs `<=` at exact equality) are not generated by the
  oracle. The code follows the disassembly's `c.olt` / `c.ole`, but no case proves the tie side.
- The oracle reads the four tolerances and the stale age from state 4's image. Other values in those
  words (another build or state) are not tested.
- Batches whose slot index or start runs past their arrays are not generated (writes would leave the
  test area). The port uses the same wrapping address arithmetic, untested there.
- The frame still runs over a RAM image held by `Ee`, as in F31b5.
