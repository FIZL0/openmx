# O1 — the functions the oracle was proved on. Chosen for being too small to be wrong about: a handful
# of instructions each, no globals, no calls, no allocation, so a disagreement can only be the
# interpreter. Together they still cover the FPU accumulator chain, sqrt, max/min, VU0 macro mode,
# quadword loads and stores, out-parameters and one data-dependent loop. All of them are the game's own
# inlined maths helpers, emitted once per header and called from everywhere.
# crates/ps2-oracle/tests/basics.rs calls every one of these; how it was done is in
# research/journal/2026-10-15-o1-oracle.
#
# Scalars, in f12/f13, result in f0. One instruction each.
float_max                   boot 0x00107f80 max.s: (a, b) -> the larger. The game has no clamp of its
#                                           own — call sites compose this with float_min
float_min                   boot 0x00107f90 min.s: (a, b) -> the smaller
float_abs                   boot 0x00107fe0 abs.s: (x) -> |x|
#
# Vec3, by pointer. The quadword forms read and write all four lanes, so the w lane must hold something
# defined even when only xyz are wanted.
vec3_dot                    boot 0x00107ff0 (a, b) -> dot, as mula.s/madda.s/madd.s in index order
vec3_length                 boot 0x00108920 (v) -> sqrt of that same chain over (v, v)
vec3_length_sq              boot 0x0010b270 (v) -> the chain without the sqrt. Identical code also at
#                                           0x0010b260 (a thunk) and 0x0010b250 thunks vec3_length
vec3_add                    boot 0x00111e60 (out, a, b): three add.s, three swc1 — out may alias
vec3_sub                    boot 0x00111ea0 (out, a, b): the same with sub.s
vec3_scale                  boot 0x00108890 (out, v, s in f12): VU0 macro, vmulx.xyz off a broadcast of

vec3_normalize              boot 0x00108070 (out, v): vmul/vadda/vmadd for the square, then vrsqrt —

vec4_abs                    boot 0x00108020 (out, v): builds 0x7fffffff in four lanes with lui/ori,

# I1 — the input layer. The pad poll's timer update is not a function: it is a span inside the poll,
# so the test loads these instructions into a bare interpreter and appends its own `jr $ra`. The name
# is the span's first instruction; the length is in the test.
pad_timer_add_ms            boot 0x0016aef0 30 instructions, not a function: ($s2+0x330) += $f20 ms,
#                                           where the stored value is read back as *unsigned* (bltz,
#                                           then halve-convert-double) and the sum converted back as
#                                           unsigned (c.ole.s against 2^31, then subtract the bias and
#                                           set the sign bit by hand). Falls through to the span's end,
#                                           so the test's `jr $ra` sits where the poll's `b` went.
#                                           The identical sequence at 0x0016ae68 does +0x334 (held ms)

# ---------------------------------------------------------------------------------------------------
# O2 — the arithmetic carriers. No shipped game has a function that is one `div.s` and a `jr`, so the
# oracle coverage of F1-F3 runs each op through the smallest *call-free* function in the image that
# contains it: one or two operations wide, every input an argument or a field the test writes, every
# result still readable when the function returns. They were found by disassembling every call-free
# function and looking for the ops the O1 set never reaches. crates/ps2-float/tests/oracle.rs calls
# each one over 10k generated inputs from the awkward classes — zero and minus zero, both ends of the
# denormal range, the smallest normal, the largest magnitudes, the Inf and NaN patterns the EE has not
# got, powers of two, and *pairs* with a chosen exponent difference (0, 24, 25, 26 and more). How it
# was done, and what it cannot prove, is in research/journal/2026-10-15-o2-float-oracle.
#
# The scalar FPU. Offsets are into the object the carrier is a method of; the test writes the fields it
# reads, so no RAM image is needed.
float_mul_add_into          boot 0x0025d180 (obj, a in f12, b in f13): *(obj+0x6c) += b*a as a mul.s and
#                                           then a separate add.s, with the sum also left in f0. Both
#                                           factors are arguments, so this is the full-domain mul.s
float_recip_32767           boot 0x00388a50 (obj, x): obj+0x94 = x, obj+0x90 = 32767.0 / x. div.s with
#                                           a free divisor, zero and the denormals included
float_span_rate             boot 0x002f9ab0 (obj, a, b): obj+0x64 = max(a, obj+0x64); obj+0x6c = 0.5 *
#                                           that; obj+0x68 = (b - obj+0x5c) / obj+0x6c. div.s with a
#                                           free numerator, plus max.s, mul.s and sub.s in that order
float_inv_sqrt              boot 0x00284b80 (x) -> 1.0 / sqrt(x): one rsqrt.s against a lui-built one.
#                                           The only root carrier that takes its argument whole, so the
#                                           only one that can be given a negative or a denormal
quat_two_matrix_rows        boot 0x0013f380 (q, row_a, row_b): two rows of the rotation matrix of the
#                                           quaternion at q, as eleven mul.s, two add.s, three sub.s and
#                                           the accumulator pairs mula.s/msub.s (-> row_b+0) and
#                                           mula.s/madd.s (-> row_a+0). The only call-free msub.s in the
#                                           image whose result is not overwritten before the return
float_to_i16_pair           boot 0x00302ce0 (out, &a, &b): out[0] = (short)(int)a, out[1] the same for
#                                           b, as cvt.w.s + mfc1 + sh. Either half is skipped on a null

# --- F3: VU0 macro mode ------------------------------------------------------
# Call sites that exercise the vu.rs model. The first two are small and pure and are the cheapest way
# to prove VU0's divider and its chop against the real code; the last two need the MAC flag, which
# ps2-oracle's interpreter does not keep yet (it has no cfc2/$vi17).
vu_scale3_recip        boot  0x001088f0 9 insns: Q = 1.0/f12 (vdiv), then the xyz of the vec4 at a0 *= Q (vmulq.xyz), stored back; returns a0. Proves vdiv + vmulq.

# F4 — the transcendentals the disc actually links. The float set is fdlibm's `float` flavour (Sun's
# freely-distributable libm, as shipped in the SDK's libm.a), compiled with every decimal constant
# rounded *toward zero*: S1 is 0xbe2aaaaa, one ulp below fdlibm's own 0xbe2aaaab, and so on through
# every polynomial. There is **no atan2f and no expf/logf in the image at all** — see the journal entry
# research/journal/2026-10-15-f4-libm for the full inventory and for what the game uses instead.
# `sqrtf` is not a function: all 305 square roots are an inlined `sqrt.s`.
# sinf, cosf, atanf, powf, fmodf and sqrtf are proved bit-exact against crates/ps2-float/src/libm.rs
# over every exponent an f32 has: cargo test -p ps2-oracle --test libm (52k inputs).
#
# The float set. One argument in f12 (two for powf/fmodf: f12, f13), result in f0.
sinf                        boot 0x0040aac0 fdlibm sinf: |x|<pi/4 -> kernel_sinf, else rem_pio2f + the
#                                           kernel the quadrant picks. Only 3 call sites — the game does
#                                           its angles with its own helpers, not with libm
cosf                        boot 0x0040a820 fdlibm cosf, the same shape
powf                        boot 0x00406d20 fdlibm __ieee754_powf. 0x0040abf0 is the thunk the game calls
fmodf                       boot 0x00406b50 fdlibm __ieee754_fmodf: exact, integer shift-and-subtract,
#                                           no rounding anywhere. Thunk at 0x0040abd8, 15 call sites
sqrtf                       boot 0x0011b880 the game's own one-instruction sqrtf: `sqrt.s $f0,$f12` and
#                                           nothing else. Every other square root in the image (305 of
#                                           them) is the same instruction inlined, so this *is* the
#                                           game's sqrtf, and it rounds to nearest like all EE divides
atanf                       boot 0x0040a478 fdlibm atanf, aT[0..10] from the table at 0x0044aa5c. One
#                                           call site. No atan2f to pair it with
#
# The float internals, exposed because a disagreement in sinf is always in one of these.
kernel_sinf                 boot 0x00409900 (x, y, iy) -> sin(x+y) for |x| <= pi/4; iy!=0 means y matters
kernel_cosf                 boot 0x00408f48 (x, y) -> cos(x+y), with the 1-z/2 split above |x|>0.3
rem_pio2f                   boot 0x00407500 (x, &y[2]) -> n, y0+y1 = x - n*pi/2. Exact to |x| <= 2^7*pi/2
kernel_rem_pio2f            boot 0x00409098 the big fixed-point reduction rem_pio2f falls back to:
#                                           (x[], &y[2], e0, nx, prec, two_over_pi). rem_pio2f passes
#                                           prec=2 and the table at 0x0044a420 (198 ints, the 8-bit
#                                           digits of 2/pi). init_jk = {4,7,9} at 0x0044a9b8, and the
#                                           eleven pieces of pi/2 at 0x0044a9c8 (six of them one ulp
#                                           below fdlibm's source, the toward-zero rounding again)
floorf                      boot 0x0040a920 fdlibm s_floorf, called by kernel_rem_pio2f
scalbnf                     boot 0x0040a9f8 fdlibm s_scalbnf, but with no gradual-underflow path: below
#                                           the smallest normal it saturates to +-0 through tiny*tiny,
#                                           because this FPU has no denormals to return

# `quat_two_matrix_rows` (0x0013f380) is the scalar pair of rows, a1 the forward axis (matrix row 2)

# the call and give *that* to the port. Generating f12 and f13 keeps those two lanes varying.

#                                      matrix. Also writes obj+0x68, +0x78, +0x19c and +0x1a0

#                                      first (vaddx.w off vf0). in_stride 0 means "same as out_stride";
#                                      n <= 0 does nothing

#                                      look-at. row1 = normalised up, row2 = normalised forward, row0
