  sign-in, uploads), `crates/hst/src/play/main_menu/mods_screen.rs` + `mods_screen/grid.rs` (Browse as a picture
  grid, kind tabs), `web/site.js` (the page side)
- the bugs opentennis hit afterwards, built in from the start this time (`./kit plan` in that repo, or grep its
  plan/DONE.md for the ID):
  - **B204:** stream downloads with progress, because a 490 MB zip held in memory crashed the browser
  - **B242:** phones follow the CDN redirect and lose the Range header, so they get a 200 instead of a 206
  - **B358:** iOS home-screen webapp OPFS `createWritable` fails, so write through the worker's sync access handle
  - **M116:** listing main + every open PR's tree is 75+ requests, so read the listing in one go and cache it
  - **B248:** ids, not names, so two mods with the same name both install
  - **B259:** stale previews after an update

  - **B372/B373:** a picture grid with kind tabs
  - **B603:** the token file is written private from the start

## What a mod is here

openmx's mods are the kinds in openmx-mods' standard (`~/repos/openmx-mods/standard/OPENMX-TRACK-STANDARD.md`)
and the shell's `mods/` folder (`crates/openmx/src/track_mods.rs`, `trick_packs.rs`):

- **Tracks:** `mods/tracks/<id>/`
- **Trick packs:** `mods/tricks/<id>/`
- **Music:** `mods/music/<id>/`
- **Textures:** if the shell reads a texture-pack folder by then

On the browser these go in its OPFS `mods/`. Store layout, one folder per mod whatever its kind:

```
mods/<id>/mod.zip       the mod folder as the shell reads it, zipped
mods/<id>/meta.json     id, kind (track|tricks|music|…), name, author, source game (MX Unleashed, MX vs. ATV
                        Unleashed, original…), version, size, sha256 of mod.zip, the standard's version
mods/<id>/preview.webp  a 16:9 picture (a track: a --shot-pose overview, as track_previews.rs makes)
```

Uploads from accounts that aren't members open a PR and go live at once. Browse lists `main` (Verified) and the
open PRs, as opentennis's does.

## P198 — Browse and install (desktop and browser)

- A **Mods** entry on the main menu, the front end's style (P118's menu).
- **Tabs per kind**, and Browse as a picture grid: name, author, source game, size, Verified, Installed / Update.
- **Install:**
  - check the sha256, then the full *Mods are data only* checks: zip entry paths, extensions, counts and sizes
    measured while unpacking, the hostile-input parsers the shell already has
  - unpack into `mods/<kind>/<id>/` (`store.json` beside it records the sha and Verified)
  - an installed track shows up in track select straight away, with no restart
- **Remove, Update, Report:** Report opens a Community discussion prefilled with the mod's id.
- **Proof:**
  - a set of bad mods, each rejected whole and leaving nothing behind
  - a seeded fuzz loop over the zip and meta readers
  - a test listing a fake store served on localhost, the way the netplay tests serve a relay
  - the headless-chromium check installing a mod in the browser

## P199 — Upload, My mods, Upload all (after P198)

- **Sign in:** paste a Hugging Face write token (the `settings/tokens/new?tokenType=write` link, as opentennis's
  `TOKENS`). It is stored private: `hf-token.txt` beside settings.txt at 0600, or localStorage in the browser.
- **Upload my mod:**
  - show the rules first: you're responsible for what you share
  - run the same checks as install, then build `meta.json` and the preview, and commit `mods/<id>/` as a PR
  - re-uploading onto the player's own open PR overwrites it
- **My public mods:** their PRs and their merged mods, with ✕ to take one down.
- **Upload all:** one commit per mod in the background, with a status line per mod.
- **The dataset card:** write `README.md` for FIZL0/openmx-mods (what the store is, the layout, the rules: uploads
  are the uploader's responsibility, no game data checks, takedowns through Community) in
  `research/p199/dataset-README.md`.
  - If `~/.config/openmx/hf-token.txt` holds a write token for FIZL0, commit the card with it.
  - Otherwise add a plan/HUMAN.md step: "upload research/p199/dataset-README.md as README.md on
    https://huggingface.co/datasets/FIZL0/openmx-mods/upload/main".
- **Seed the store:** upload the mods in `~/repos/openmx/mods` and openmx-mods' made mods (MX vs. ATV tracks,
  trick packs, music) that the user already ships, so Browse isn't empty at release. Do it with the user's token
  only, and ask through HUMAN.md if there is none.
