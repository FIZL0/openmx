# S496 — pilot: lifting instead of porting (user 2026-10-31)

## Why

MXA (a Unity client for MX vs. ATV, binaries at github.com/ItZFerret/mxa-releases, no license) runs its
whole simulation from `mxacore.dll`, a C **lift** of the MX vs. ATV PC exe: decompiler output translated
close to line for line, with the exe's objects in an emulated flat 32-bit memory (`*g_mx + this + 0x1778`),
the exe's own field offsets and vtable addresses, and `this`/arguments in ECX/EDX as in the exe. In about
three weeks it had every machine, AI riders, races, scoring and cameras. The port here is deeper and
proven, but goes one subsystem at a time.

The user asked for a pilot to measure the lift approach on openmx before deciding where to use it. The
reference is git-ignored in `context/mxa/` (read `context/mxa/NOTES.md`). It is reference only:
**no MXA code, decompiled or rewritten, comes into the repo.**

## What to build

- `crates/game-lift`: a `Mem` arena holding the part of the ELF's heap the lifted code touches, laid out
  as the original lays it out, with typed accessors (`u32`, `F` from ps2-float, `Vf`) at `this + offset`.
  Floats go through ps2-float, so lifted code stays deterministic for ggrs on desktop, wasm and iOS.
- Lift the start gate (its state machine and drop) and the AI rider's per-tick step (waypoint follow,
  throttle/steer decision, avoid) from SLUS-20767, close to line for line from the Ghidra decomp.
  Function names say what they do; addresses go in `research/oracle.txt` and the journal, as now.
- Bridge: the AI bike lives in the arena; each tick the bridge hands its pose and chassis to the
  renderer and its contact shape to rider_contact. The player's bike stays on game-sim.
- One AI bike on Supercross01 behind the gate, reachable from a flag (`--ai 1`), off by default.

## How it is proved

- Every lifted function: ps2-oracle runs the original on a RAM image, and the lift runs on the same
  bytes in `Mem`; the RAM out must match. That is cheap here because the layout is the same, which is the
  whole point of lifting.
- End to end: an AI bike leaves the gate and completes a lap of Supercross01.

## What to record (the point of the pilot)

In the journal: functions lifted, hours (or agent sessions) per function, proof failures and their
causes, and the bridge's size in lines. Compare with recent port tasks of similar scope (S-tasks from
plan/DONE.md), so the user can decide whether S12/S13/S231/S232/S233 go the lift way.

## Rules this needs

`./kit audit` bans bare hex in shipped code, and lifted code is full of field offsets. Before landing,
ask the user to approve an AGENT.md exemption for `crates/game-lift` (struct offsets allowed, retail
addresses and decompiler names still banned). Do not edit AGENT.md without that approval.

## Not decided

- Whether the lift should come from SLUS-20767 (MIPS: VU0 macro ops, 128-bit registers, delay slots)
  or from MX Unleashed's **Xbox** `default.xbe` (x86, the same game; see context/mxa/NOTES.md). The
  pilot uses SLUS, because ps2-oracle can prove it.
