The rules are in `PLAN.md`; this is only the backlog. Read it with `./kit plan` (headings and ids),
`./kit plan next` (the next task to take) and `./kit plan brief <ID>` (everything you need for one task:
the line, its long form, its journal and the files, with line counts and recent commits). Never open this
file whole, and never edit a checkbox by hand — `./kit plan tick <ID>`, `./kit plan block <ID> "<why>"`,
`./kit plan unblock <ID>`, `./kit plan move <ID> …`, `./kit plan add <PREFIX> "<text>"`.

One line is one task, finishable in one session:

    `- [ ] **ID** what it has to do | files: a.rs, dir/** | after: X | test: name | journal: slug`

`files:` is what the task touches: the runner keeps two agents off the same code by it (and off what running
and finished-unmerged tasks have touched), so keep it honest and specific. `after:` ids it waits for. `test:`
names the test that will prove it; a task with no `test:` either is not a port task or is not thought through
yet. `journal:` is the journal directory under `research/journal/`. Only the fields count: prose is never read
for files or ids. `./kit plan add P "text" --files a.rs,dir/** --after X --test name` writes them.
Keep the line to what it has to do and how it is proved, about 400 characters: the why, the history and
the design go in `plan/<ID>.md`, which `brief` pastes in whole.
`- [x]` done (it moves to `plan/DONE.md`), `- [~]` blocked with the reason on the line, `(in X)` is a subtask of X.

**Ids are permanent.** They end up in journal directories, commit messages, test names and code comments.
If a task comes back, reopen it under its own id; never renumber, and never give an old id to new work.

Prefixes: `D` disc · `R` decompilation · `C` the frame and captures · `F` arithmetic · `O` oracle ·
`A` acceptance harness · `I` input · `S` simulation · `V` rendering · `K` the kit itself ·
`P` the playable shell and how it rides · `N` online play.

### Phase 9 — it has to feel like the game

The port draws a track, loads a 125 off the disc, runs the ported physics and poses a rider. Ridden, it
does not feel like MX Unleashed yet: the keyboard barely registers, the bike will not stand still, and
nothing on the bike itself moves. Everything here is measured in the shell with a person at the controls
or with `--trace`, and every one of them is something you can feel in the first ten seconds of riding.

Two rules carried from the phases above: a number that reaches the simulation is still proved against the
original (oracle or capture), and a number that only reaches the picture matches by eye. These tasks are
ordered by how much of the ride they fix, not by size.

### Phase 12 — riding together: split screen, menus, online

The original has two-player split screen; the port wants four on one screen now and maybe eight later, plus
online play, with a front end where you pick and change your rider and bike and add or remove controllers
(user, 2026-10-20). opentennis (`/home/rycs/repos/opentennis`, ours) has solved most of the non-simulation
half already: take it from there (AGENT.md, "Take it from opentennis first"). The menus are in MX Unleashed's
style rather than 1:1, the way AGENT.md lets the front end be. Everything here is an addition: one player, offline,
with nothing switched on must ride bit for bit as it does today, acceptance runs included.

### Phase 13 — how it looks, sounds and plays

The user's list of 2026-10-20: the world's textures and light, the front end's look, new controls with the
original's as a setting, the machine and the overlay in the menus, sound and music, a multiplayer main menu,
and the lag, first, because the GPU renderer (P44) is what the rest draws on. Rendering, sound and the front end are by eye and ours to design (AGENT.md); the simulation
must not move a bit, and every switch's original setting rides exactly as today.

### Phase 14 — mods: tracks from other games

The other Rainbow games ship the same track formats: MX vs. ATV Unleashed and Untamed use MX.PSR's container,
the `.res`, the PLN v7 `.trn`, the INI `.scn` and the `.col` (survey: github.com/FIZL0/openmx-mods,
`notes/mxvatv.md`). openmx-mods turns their maps, and real elevation data, into track mods; these tasks are
the port's half. The rule from AGENT.md holds: with no mods present the game is the original, and every
replay hash is unchanged.
