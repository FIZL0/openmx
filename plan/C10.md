## What C10 does

Play it the way S93 did (research/s93/play_capture.sh: Stop, Reset, recorder on a `start` trigger, Play
the copy, resume) in a kit copy whose PCSX2.ini says `[Pad2] Type = DualShock2` (check it; copies made
before K4 say None and P2 rides idle). One playback per spec if the recorder cannot poll everything in a
tick; every capture must have no gap and no guard miss.

Columns, for both riders (`p1_`/`p2_`, as `watch/split.toml`):

- everything `watch/split.toml` has (vehicle, chassis, the 11-entry collision record, bike actor, both pads);
- what C6 added to acceptance.toml for one rider: wreck reason and state, the trick state (armed, group,
  direction, requested, running), the air step's on-the-ground flag, the backflip's armed/firing state;
- the rider's bones (S74's `bones_watch.py` / `watch/rider-joints.toml`) and the body's mode (riding /
  riding ragdoll / wrecked ragdoll / put-back), so the ragdoll and the animations can be compared per tick;
- the animation state the drawn body plays: clip, frame, blend/ramp, foot-down;
- the moving platform: for each wheel and body contact, the struck record (+0x74) and whether it is a path
  car (which one), and each path car's transform and velocity (S81/S136's path-car fields) on rows where a
  rider touches one.

Put the captures in `context/capture/2p/` (a subfolder: older readers stay green), and copy them to every
slot's `context/capture/2p/` when done — the tasks after this one run in any slot.

Save a state at the tick before every event below (research/s93/play_at.sh + at_ticks.py, NominalScalar
0.25) and turn each into a RAM image in `context/states/c10-<tick>.ram`; copy those to every slot too.

## The index

Write it into the journal as tables, so no later task reads 6,000 rows. Every one with tick (frame_counter
and row), which rider, and what the original did:

1. every **wreck**: wreck reason, the clause that fired (landing, air, body hit, rider-rider…), the
   quantity it judged and its value on the firing tick;
2. every **near miss**: a hard or crooked landing, a hit or a steep slope ridden out — the same quantity
   and its value, so the wreck thresholds have a ridden-out side as well as a wrecked side;
3. every **world contact** (props, crates, signs, trees, walls): which record, ridden out or wrecked;
4. every **rider-vs-rider contact** (S88's kinds: head-on, side swipe, landing on, into a wrecked rider);
5. every stretch **on a truck / trailer** (path car): on and off ticks, which car, its speed, whether the
   rider stays on;
6. every **ragdoll** stretch: wreck tick to put-back tick, per rider;
7. **animations**: tricks (id and name), backflips, foot-down stops, reverse, lean extremes, put-backs —
   as tick ranges.

Add the readers to `crates/game-sim/tests/split.rs` (or a sibling `two_p.rs`) and a test that loads the
captures and asserts their row counts, both riders' lanes and every indexed event at its tick. Raise a
count past the data once to prove the test runs and does not skip (a passing check hides skips).

## "Source of truth"

From C10 on, `2p` is the human recording of record (A6 says so in the code and docs): every new test of
wrecks, collisions, ragdoll, rider-vs-rider, moving platforms, wreck thresholds and animations reads it, and
when an existing test of those subjects reads first_recording / recording2 / animandpump / the S93 tapes,
the task in its area adds the 2p case beside it. Old bit-exact pins are not deleted for it; a task may drop an
older fixture only when the 2p case covers the same thing, and says so.

thresholds; S157 world collisions; S158 rider-vs-rider; S159 riding the trucks; S160 the ragdoll; V90
animations.
